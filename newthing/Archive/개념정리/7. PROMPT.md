# Claude Code 프롬프트 치트시트

프롬프트 6종 + ultrathink/subagent. 옆에 두고 보는 용도.

---

## A. 구현·생성 — 새로 만들 때

**담을 것:** 스택+버전 / 기능 범위 / 디자인·제약 / 작업 순서 / 완료 기준

```
React 18 + TypeScript로 할 일 앱을 만들어줘.
요구사항: 추가/삭제/완료 토글, localStorage 영속화, Tailwind, 모바일 반응형.
먼저 컴포넌트 구조를 제안하고 내 확인을 받은 뒤 구현해줘.
완료 기준: 새로고침해도 목록 유지, 빈 목록 상태 UI 표시.
```

→ "구조 제안 → 확인" 게이트 + 완료 기준이 한 단계 위.

---

## B. 버그 수정

**담을 것:** 증상 / 위치(@파일) / 방법 / 기대 동작

```
[좋음]
체크아웃에서 만료된 카드 사용자에게 오류가 납니다.
@src/payments/ 토큰 갱신 로직을 확인하고, 먼저 실패하는 테스트를 작성한 뒤 수정해줘.
기대 동작: 만료 카드면 갱신 토큰으로 재시도, 실패 시 명확한 에러 표시.
```

```
[나쁨]
체크아웃에 버그가 있어. src/payments/ 보고 조사해서 고쳐줘.
```

→ 같은 작업, 다른 품질. 증상·방법 없으면 추측 + 과잉 수정 위험.

---

## C. 함수·유닛 스펙 (few-shot)

**담을 것:** 함수명 / 입력→출력 예시 / 범위 / 테스트 실행

```
validateEmail을 구현해줘.
케이스: 'user@example.com' → true, 'invalid' → false, 'user@.com' → false
이 케이스는 통과시키되, 그 외 엣지케이스(user+tag@, 서브도메인 등)는 합리적으로 판단해줘.
구현 후 테스트를 실행해줘.
```

→ 입출력 예시가 곧 스펙. 까다로운 건 "어디까지 엄격히"를 명시.

---

## D. Explore → Plan → Confirm → Do (확인 게이트)

**언제:** 리팩토링·설계 등 크거나 되돌리기 어려운 작업

```
결제 모듈을 모듈화하려고 해. @src/payments/ 를 분석하고,
가능한 접근을 2~3개 제안해줘. 장단점도 같이.
내가 하나 고를 때까지 코드는 건드리지 마.
```

→ 제안 → 선택 → 실행으로 끊어, 방향 틀렸을 때 손해 방지.

---

## E. ultrathink — 깊은 추론 (Claude Code 전용)

**언제:** 복잡한 아키텍처 결정, 추적 어려운 버그, 깊은 분석. 단순 작업엔 X.

```
ultrathink: 모놀리식(@src/)을 마이크로서비스로 전환하는 최적 전략을 설계해줘.
ultrathink: @src/queue/processor.ts 의 race condition이 왜 발생하는지 깊이 분석해줘.
```

주의:

- CLI에서만 작동. 웹 채팅·API에선 그냥 단어.
- "31,999 토큰"은 옛 설명. 지금은 그 한 턴만 높은 effort를 트리거.
- 세션 내내 깊게 → `/effort high`.
- 이미 시간을 잡아먹은 어려운 문제에만 아껴 쓰기.

---

## F. subagent — 일을 떼어 위임

**왜:** 컨텍스트 보호. 탐색·로그·막다른 시도 노이즈를 격리하고 메인엔 요약만.

```
조사:   subagent로 인증 시스템이 토큰 갱신을 어떻게 처리하는지,
        재사용할 OAuth 유틸이 있는지 조사해줘.
테스트: subagent로 테스트를 실행하고 실패한 것만 보고해줘.
리뷰:   @agent-reviewer 로 이 코드를 보안·엣지케이스 관점에서 검토해줘.
```

- 독립된 컨텍스트·프롬프트·도구·권한·모델을 가진 별도 인스턴스.
- 정의: `.claude/agents/`의 마크다운(YAML frontmatter + 본문=시스템 프롬프트).
- 배치 작업은 낮은 effort 권장(비용 절약).

## 한눈에

|종류|쓰는 때|한 줄|
|---|---|---|
|A 구현·생성|새로 만들 때|스택·범위·순서·완료기준|
|B 버그 수정|버그 잡을 때|증상+위치+방법+기대|
|C 함수 스펙|입출력 명확한 함수|예시가 곧 스펙|
|D 확인 게이트|크거나 위험한 작업|제안→선택→실행|
|E ultrathink|어려운 한 문제|CLI 전용, 한 턴만|
|F subagent|탐색·테스트·리뷰 위임|노이즈 격리, 요약만|

**A~D = 프롬프트 쓰는 법(기본기) · E·F = Claude Code 기능(깊이 더하기 / 일 떼어내기)**

공통 원칙 4가지: ① 위치·맥락 명시(@파일) ② 명확한 목표 + 완료 기준 ③ 방법 지정(test-first 등) ④ 큰 작업엔 확인 게이트

# Claude Code 프롬프트 레시피 (종류별)

각 레시피 = 빈칸 채우기 틀 + 좋은 예시. 옆에 두고 골라 쓰는 용도. 공통 원칙: ① 위치(@파일) ② 명확한 목표 + 완료 기준 ③ 방법 지정 ④ 큰 작업엔 확인 게이트

---

## 1. 코드 리뷰

**틀:** @파일 + 검토 관점(번호) + 출력 형식 + "수정 말고 검토만"

```
@src/services/payment.ts 를 리뷰해줘. 코드는 바꾸지 말고 검토만.
다음 관점에서:
1. 에러 핸들링이 충분한가
2. 놓친 엣지 케이스가 있는가
3. 성능 개선 포인트가 있는가
4. 네이밍·가독성은 괜찮은가
각 항목별로 라인 번호와 개선 코드 예시를 포함해줘.
```

포인트: "검토만"을 명시해 Claude가 멋대로 수정하는 것 방지. 깊은 리뷰면 subagent 위임.

---

## 2. 버그 수정

**틀:** 증상 + 재현 경로 + 기대 동작 + @위치 + 제약(+재현 테스트 먼저)

```
버그: 장바구니 수량을 0으로 줄이면 음수가 되어 결제 금액이 마이너스가 됨.
재현: 상품 추가 → 수량 감소 버튼 연타 → 수량 -1.
기대 동작: 수량 최소 1, 0이 되면 항목 삭제.
관련 파일: @src/hooks/useCart.ts @src/components/CartItem.tsx
먼저 이 버그를 재현하는 실패 테스트를 작성한 뒤 수정하고, 기존 테스트가 깨지지 않게 해줘.
```

포인트: "재현 테스트 먼저"가 핵심. 수정이 진짜 고쳤는지 증명됨.

---

## 3. 기능 구현 (새로 만들기)

**틀:** 스택+버전 / 범위 / 제약 / "구조 제안 → 확인 → 구현" / 완료 기준

```
React 18 + TS로 알림 설정 패널을 만들어줘.
범위: 이메일/푸시 토글, 빈도 선택(즉시/일간/주간), 저장 버튼.
제약: 기존 Settings 레이아웃·Tailwind 토큰 재사용, 새 의존성 추가 금지.
먼저 컴포넌트 구조를 제안하고 내 확인을 받은 뒤 구현해줘.
완료 기준: 저장 후 새로고침해도 설정 유지, 토글 즉시 반영.
```

포인트: 확인 게이트 + 완료 기준이 한 단계 위. "기존 것 재사용"으로 과잉설계 방지.

---

## 4. 함수·유닛 (few-shot)

**틀:** 함수명 + 입력→출력 예시 + 범위 + 테스트 실행

```
parseAmount를 구현해줘.
케이스: '1,000' → 1000, '$12.50' → 12.5, '' → 0, 'abc' → null
이 케이스는 통과시키되, 통화 기호·천단위 구분자 외 형식은 합리적으로 판단해줘.
구현 후 테스트를 실행해줘.
```

포인트: 입출력 예시가 곧 스펙. 까다로운 건 "어디까지"를 명시.

---

## 5. 리팩토링 (확인 게이트)

**틀:** 대상 + 목표 + "접근 2~3개 제안, 고를 때까지 멈춤"

```
@src/utils/api.ts 의 중복된 fetch 로직을 정리하고 싶어.
가능한 접근을 2~3개 제안해줘. 장단점도 같이.
동작은 그대로 유지하고, 내가 하나 고를 때까지 코드는 건드리지 마.
```

포인트: "동작 유지"를 박아 행동 변경 방지. 제안 → 선택 → 실행.

---

## 6. 탐색·이해 (읽기 전용)

**틀:** @대상 + 알고 싶은 것(번호) + "바꾸지 마"

```
@src/auth/ 를 읽고 이해해줘. 코드는 바꾸지 마.
1. 세션·로그인을 어떻게 처리하는지
2. 토큰 갱신 흐름
3. 비밀(secret) 환경변수 관리 방식
```

포인트: Plan Mode나 subagent와 잘 맞음. 큰 작업의 1단계.

---

## 7. 깊은 분석 (ultrathink · CLI 전용)

**틀:** `ultrathink:` + 어려운 문제 + @참조

```
ultrathink: @src/queue/processor.ts 의 race condition이 왜 발생하는지 깊이 분석해줘.
ultrathink: 모놀리식(@src/)을 마이크로서비스로 전환하는 최적 전략을 설계해줘.
```

포인트: 어려운 한 문제에만. CLI에서만 작동, 한 턴만 적용. 세션 내내면 /effort high.

---

## 8. 위임 (subagent)

**틀:** "subagent로 ~ 하고 [요약만] 보고해줘"

```
조사:   subagent로 인증이 토큰 갱신을 어떻게 처리하는지, 재사용할 OAuth 유틸이 있는지 조사해줘.
테스트: subagent로 테스트를 실행하고 실패한 것만 보고해줘.
리뷰:   @agent-reviewer 로 이 코드를 보안·엣지케이스 관점에서 검토해줘.
```

포인트: 탐색·테스트·리뷰처럼 노이즈 많은 일을 떼어내 메인 컨텍스트 보호.
