### subagent 

전체 흐름 관리 

  
예) 코드 리뷰어와 디버거를 서브에이전트로 정의 
```
{
  "code-reviewer": {            // ← 에이전트 이름(key). 호출할 때 이 이름 사용

    "description": "코드 변경 후 자동으로 리뷰",   // ← 언제 이 에이전트를 쓸지 판단하는 기준

    "prompt": "당신은 시니어 코드 리뷰어입니다...", // ← 이 에이전트의 시스템 프롬프트(역할/성격)

    "tools": ["Read", "Grep", "Glob", "Bash"],    // ← 이 에이전트가 쓸 수 있는 도구 제한

    "model": "sonnet"           // ← 이 에이전트가 사용할 모델

  },

  "debugger": {

    "description": "오류 및 테스트 실패 디버깅 전문가",

    "prompt": "당신은 전문 디버거입니다..."

    // tools, model 생략 → 기본값 사용

  }

}

```

예) 시스템 프롬프트를 커스텀마이징 할수 있다

```
# 파일에서 시스템 프롬프트 로드 (인쇄 모드만)

```

## 📝 3-3. Hook JSON 구조

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "terminal-notifier -title 'Claude Code' -message '알림이 있습니다' && afplay /System/Library/Sounds/Ping.aiff &"
          }
        ]
      }
    ]
  }
}
```

**JSON 구조 분해:**

- **이벤트 타입** (`Notification`) — 언제 실행할지
- **matcher** (`*`) — 어떤 상황에 매칭할지 (와일드카드 = 전부)
- **hooks 배열** — 실행할 Hook 목록 (여러 개 가능)
- **command** — 실제 실행할 셸 명령어
